soc-framework v1.0 — analyst@soc:~$█

// SOC OPERATIONS FRAMEWORK

The defender's cycle — monitor, triage, investigate, contain, recover, improve.
OVERALL PROGRESS0%
📊
MONITOR & DETECT
Continuous visibility across the environment. You can't respond to what you can't see.
Checklist
Review SIEM dashboard for the shift
Check alert queue, open incidents, and health of log ingestion
Verify all critical log sources are reporting
EDR, firewall, DNS, proxy, auth/IdP, cloud audit logs
Tune noisy detection rules
Reduce false-positive rate without losing true-positive coverage
Review threat intel feed for new IOCs
Cross-reference against internal telemetry
Baseline normal traffic and user behavior
Needed so anomalies actually stand out
Key Tools
Splunk
SIEM / log search
Elastic (ELK)
Log aggregation
Microsoft Sentinel
Cloud SIEM
CrowdStrike
EDR telemetry
Suricata / Zeek
Network IDS
MISP
Threat intel
🚨
TRIAGE & PRIORITIZE
An alert fires. Decide fast: noise, or something that needs a human right now.
Checklist
Confirm the alert isn't a known false positive
Check suppression list and prior similar alerts
Assign severity (P1–P4)
Based on asset criticality + potential blast radius
Check asset criticality (crown jewel vs. low-value)
A workstation alert ≠ a domain controller alert
Correlate with other alerts in the same window
One alert alone may be noise; three together may be a chain
Log the initial assessment and open a case
Tools: TheHive, Jira, ServiceNow SecOps
Severity Guide
P1Active compromise on critical asset — respond now
P2Confirmed malicious activity, contained blast radius
P3Suspicious but unconfirmed — needs investigation
P4Low-risk / policy violation — routine handling
🔬
INVESTIGATE
Establish what actually happened: entry point, scope, and root cause.
Checklist
Pull logs from the affected host(s)
Process, network, auth, and file-system events
Reconstruct the process/execution timeline
Tools: EDR console, Velociraptor, KAPE
Identify indicators of compromise (IOCs)
Hashes, IPs, domains, registry keys, scheduled tasks
Check for lateral movement
Review auth logs across other hosts for the same IOCs
Map activity to MITRE ATT&CK techniques
Helps standardize the incident narrative
Determine full scope of compromise
Every account, host, and data set touched
Key Tools
Velociraptor
Live forensics
KAPE
Artifact collection
Volatility
Memory forensics
Defender/CrowdStrike
EDR timeline
🧯
CONTAIN & ERADICATE
Stop the bleeding, then remove the cause completely — not just the symptom.
Checklist
Isolate affected host(s) from the network
EDR network isolation, not full shutdown (preserve evidence)
Block malicious IOCs at perimeter
Firewall, proxy, DNS sinkhole, WAF rules
Disable or reset compromised accounts
Force password reset + revoke active sessions/tokens
Remove persistence mechanisms
Scheduled tasks, services, registry run keys, cron jobs
Patch or close the exploited vulnerability
Confirm the entry point can't be reused
♻️
RECOVER & VALIDATE
Bring systems back carefully, and prove the threat is actually gone.
Checklist
Restore from a known-clean backup
Verify backup predates the compromise
Monitor restored systems for reinfection
Heightened alerting for 1–2 weeks post-incident
Validate systems are clean before reconnecting
Full AV/EDR scan + integrity check
Gradually restore user access
Staged rollout, not all-at-once
Confirm normal business operations resumed
Sign-off from affected business unit
📈
REPORT & IMPROVE
Every incident should make the next one faster to catch and easier to stop.
Key Metrics
MTTD
Mean time to detect
MTTR
Mean time to respond
Alert Vol.
Alerts per shift
FP Rate
False positive %
Checklist
Write the full incident timeline
Detection → triage → containment → recovery, with timestamps
Calculate MTTD / MTTR for this incident
Compare against team baseline
Update or create detection rules
Close the gap that let this slip through initially
Run a blameless lessons-learned session
What worked, what didn't, what's changing
Update runbooks with new findings
So the next analyst doesn't start from zero
redteam-framework v1.0 — operator@rt:~$█

// RED TEAM ENGAGEMENT FRAMEWORK

Authorized adversary simulation — scoped, objective-driven, always debriefed with the defenders.
Authorization is the first control. Every phase below assumes a signed Rules of Engagement (ROE) and written client authorization. No ROE, no engagement — full stop.
OVERALL PROGRESS0%
📜
SCOPE & RULES OF ENGAGEMENT
Define what "success" means, what's off-limits, and who to call if something goes wrong.
Checklist
Get written authorization signed by the client
Must name the engaging party with authority to authorize testing
Define engagement objectives
e.g. reach domain admin, access a specific data store, test detection response
Define in-scope and explicitly off-limits systems
Production vs. staging, third-party systems, physical sites
Agree testing style: black box, grey box, or assumed breach
Determines starting knowledge/access level
Set an emergency stop procedure and contact
Who can call off the engagement immediately, and how
Agree whether the SOC will be notified in advance
Announced test vs. purple team vs. true no-notice
🕵️
RECONNAISSANCE & OSINT
Map the organization the way a real adversary would — passively, before any active step.
Checklist
Map external footprint (domains, IP ranges, cloud assets)
Passive recon only at this stage
Identify technology stack and third-party vendors
Informs which technique categories are realistic
Identify employees/roles relevant to the objective
Only if social engineering is explicitly in scope
Review public breach data and leaked credentials
Understand what's already exposed, don't use illegally obtained data
Build a target profile document
Shared internally with the team, never with unauthorized parties
🔑
INITIAL ACCESS PLANNING
Decide which vector fits the agreed scope and objective — plan it, get sign-off, then execute within ROE.
Vector Categories (only if authorized in ROE)
EXTERNALExploiting an in-scope external vulnerability
SOCIALPhishing simulation, if explicitly scoped
PHYSICALOn-site social engineering / badge testing, if scoped
CREDENTIALPassword spraying against exposed services, rate-limited
Checklist
Confirm chosen vector is explicitly within ROE
No vector is assumed in-scope by default
Get final go/no-go sign-off before execution
Especially for social engineering or physical vectors
Log every action with timestamps
Required for the final report and any SOC correlation later
🧭
PERSISTENCE & LATERAL MOVEMENT
Move toward the objective the way a patient adversary would, while staying inside the agreed boundaries.
Checklist
Maintain access only within scoped systems
Never pivot into explicitly excluded assets
Map the path toward the objective, not every possible host
Efficiency matters — this isn't a full network compromise
Respect any agreed detection thresholds
In purple team exercises, deliberately trigger specific detections
Document each step against MITRE ATT&CK
Makes the final report directly actionable for the SOC
Avoid any destructive or data-exfiltrating action
Proof of access is enough — never remove real data
🏁
OBJECTIVE & IMPACT DEMONSTRATION
Reach the agreed goal, capture proof, then stop.
Checklist
Confirm the objective as defined in scope has been reached
e.g. domain admin, access to defined data store
Capture minimal proof of impact
Screenshot/log evidence — not bulk data extraction
Stop active testing once objective is proven
Continuing further adds risk without adding value
Begin cleanup of any implants/access used
Track everything so nothing is left behind post-engagement
🤝
REPORTING & PURPLE TEAM DEBRIEF
The engagement's real value: what the defenders learn from it.
Checklist
Write the full attack narrative / kill chain
Every step, mapped to MITRE ATT&CK
List concrete remediation recommendations
Prioritized by what would have stopped the chain earliest
Confirm all access and implants were fully removed
Sign-off from both red team and client IT
Hold a purple team debrief with the SOC
Walk through what was/wasn't detected, and why
Hand off detection gap list to the SOC for tuning
Closes the loop between red and blue
